# AbroBiz final security risk register

Audit date: 2026-09-01. Severity reflects release impact, not exploit certainty. The register is based on repository evidence; live configuration findings remain unverified.

| ID | Severity | Location | Risk / impact | Recommended fix and release exit |
|---|---|---|---|---|
| R-01 | CRITICAL | `.env.example` | File contains values that are not placeholders, including server/provider credentials. A committed example file can disclose credentials. | Immediately revoke/rotate every exposed server/provider credential, replace with placeholders, inspect git history and Vercel/Supabase logs. Release stop until confirmed clean. |
| R-02 | CRITICAL | `.env`, `src/lib/supabaseClient.ts`, `supabase/config.toml` | Local frontend environment points at the old Supabase project while CLI config points at canonical project. Signups, email, OAuth, and data may target different projects. | Align Vercel, local production configuration, Auth, Functions, and migrations to canonical project; prove with masked host and runtime smoke tests. |
| R-03 | CRITICAL | Production state unavailable | No independent evidence for live RLS, migrations, DNS/TLS, Vercel variables, provider delivery, or Google/Turnstile configuration. | Run preflight and smoke plan with sanitized evidence. No GO decision before this gate. |
| R-04 | HIGH | `supabase/functions/telegram-webhook/index.ts:5,8` | `detectAllowedFile` is imported twice. Deno compilation was unavailable, so deployment compilation is unproven and may fail. | Remove duplicate import, run Deno type/check and function deploy in a non-production project, then smoke-test webhook. |
| R-05 | HIGH | `.env.example` and function config | Turnstile example enforcement is false; production could accidentally run fail-open if environment is copied incorrectly. | Set production enforcement true and test missing/invalid token rejection on every protected public endpoint. |
| R-06 | HIGH | Environment contract | Brief names `CORS_ALLOWED_ORIGINS`, but code reads `CORS_ORIGINS` or `CORS_ORIGIN`. Setting only the requested name leaves the actual allowlist ineffective or default-only. | Choose one canonical variable, update deployment config and docs together, and test allowed/denied origins. |
| R-07 | HIGH | `0024`, `0025`, `0028`, `0029` migrations | Unique indexes, token invalidation, `NOT VALID` constraints, and storage policy changes can cause downtime, user impact, or incomplete enforcement. | Backup, preflight, apply in order, validate constraints, and record rollback/support plan. |
| R-08 | HIGH | Vercel/Supabase/Auth dashboard | Google redirect, custom Auth hostname, branded email sender, and provider delivery are dashboard state, not guaranteed by source. | Verify exact production callback/redirect allowlists and one real disposable account end-to-end. |
| R-09 | HIGH | RLS/runtime | Static policies are extensive, but remote policy state was not introspected. Any missing migration or permissive old policy can create BOLA/tenant data exposure. | Query and review final policies on canonical project; run cross-tenant owner/admin tests. |
| R-10 | HIGH | Storage policies and existing objects | Direct browser writes are intended to be revoked and path-scoped, but existing object paths and actual bucket states are unknown. | Inventory buckets/objects, test private proof access, and verify no public proof object is reachable. |
| R-11 | HIGH | Backup/recovery operations | Repository has runbooks, but backup schedules, PITR, retention, restore ownership, and a recent restore result are not evidence-backed here. | Confirm provider settings and complete a restore drill with RPO/RTO results. |
| R-12 | MEDIUM | `src/lib/api/businesses.ts` admin list | Admin business list has a fixed 1,000-row limit and payments use fixed 200-row limits; history can be silently truncated and queries grow. | Add cursor/server pagination and indexes; define retention/reporting strategy. |
| R-13 | MEDIUM | `src/lib/useStorefrontData.ts` | A storefront refresh can perform multiple Supabase reads every 30 seconds per active browser. Hot tenants may create high read volume. | Measure at scale; add edge/API caching or consolidated public read path with safe invalidation. |
| R-14 | MEDIUM | `supabase/functions/_shared/rateLimit.ts`, DB RPC | PostgreSQL rate-limit state can become a write hotspot under abuse or a global traffic spike. | Benchmark, bound retention, monitor lock/CPU, and evaluate edge-distributed limiting. |
| R-15 | MEDIUM | `vercel.json` CSP | `img-src https:` and `media-src https:` are broad; `style-src 'unsafe-inline'` remains. This increases XSS/content injection blast radius if an unsafe URL or style path is introduced. | Narrow media/image origins where practical and migrate inline styles to nonces/hashes or accepted controlled policy. |
| R-16 | MEDIUM | `vercel.json` and SPA rewrite | HTML has no explicit no-store policy; SPA rewrite catches every path. Incorrect caching or error handling could serve stale shells or poor 404 behavior. | Verify live cache headers; use immutable assets and controlled HTML/error caching; add a safe not-found route. |
| R-17 | MEDIUM | Public hostname resolution | Tenant selection is primarily frontend hostname/slug logic; public write endpoints receive a business ID. RLS protects writes, but hostname-to-tenant binding is not a server-side request invariant. | Bind public operations to a validated published tenant context where feasible and retain business/RLS checks. |
| R-18 | MEDIUM | `import-template`, Telegram, Resend, Google, Turnstile | External dependencies are bounded but can be unavailable, quota-limited, or slow. | Track dependency latency/error budgets, circuit-break where needed, and define user-safe fallback behavior. |
| R-19 | MEDIUM | Observability helpers | Safe structured logging exists, but no live sink, alert rules, trace/correlation coverage, or retention proof is present in the repository. | Configure redacted centralized logs, alerts, dashboards, and on-call ownership; verify no secrets/PII are logged. |
| R-20 | LOW | `.env.test` | Tracked test environment contains a Supabase URL/key. The anon key is client-safe by design, but it leaks project identity and can be misused if policies are weak. | Use a dedicated disposable project, document the public-key status, and keep production identifiers out of test fixtures. |
| R-21 | LOW | `index.html`, `public/` | No `robots.txt`, sitemap, Open Graph metadata, or custom static error assets were found. | Add SEO/operational metadata after security gates; do not let this block tenant isolation. |
| R-22 | LOW | `package.json` | No lint script or dependency audit policy is configured. Version ranges are caret ranges, so installs can drift. | Pin/lock CI installs, add lint/type/test/build gates, and run scheduled dependency review. |

## Immediate release blockers

R-01, R-02, R-03, R-04, R-05, R-07, R-08, and R-09 are release blockers. R-10 and R-11 must be closed before handling real payment proofs or claiming production readiness.
